Android 14 is the release that made apps say why they run. Every foreground
service in an app targeting API 34 needs a declared type and a matching
permission, and users can hand an app a few photos instead of the whole
library. On every device, apps that target an API level below 23 can no longer
be installed.

## At a glance

|                                 |                                                                                  |
| ------------------------------- | -------------------------------------------------------------------------------- |
| Version                         | Android 14                                                                       |
| API level                       | 34                                                                               |
| Name                            | Upside Down Cake, internal; visible in the SDK constant. Public name: Android 14 |
| `Build.VERSION_CODES`           | `UPSIDE_DOWN_CAKE`                                                               |
| Release                         | Pixel rollout began 4 October 2023                                               |
| Launch devices                  | Pixel 8 and Pixel 8 Pro, announced 4 October 2023, on sale from 12 October       |
| Google Play target-API deadline | New apps and app updates from 31 August 2024 (extension to 1 November 2024)      |
| Toolchain                       | `compileSdk 34`, Android Gradle Plugin 8.1.1 or later (Studio below)             |

Google's compatibility table lists Android Studio Hedgehog (2023.1.1) and AGP
8.1.1 as the minimum for API 34. The Android 14 SDK setup page, written at
launch, recommends Flamingo (2022.2.1) or higher, and writes `compileSdk 34`
for AGP 7.0 or later. Use the newer table when the two disagree.

Google announced Android 14 with Developer Preview 1 on 8 February 2023. Beta 1
opened the Android Beta program on 12 April, and Beta 3 reached platform
stability on 7 June, with the APIs and app-facing behaviours final. The two
developer previews and the five betas are the parts that follow this overview.

Google released Android 14 and pushed its source to AOSP on 4 October 2023.
The first Pixel build (`UP1A.231005.007`), with the October 2023 security
patch, covered the Pixel 4a (5G) through the Pixel Fold and Pixel Tablet.
Google's post named Samsung, iQOO, Nothing, OnePlus, Oppo, Realme, Sharp, Sony,
Tecno, vivo and Xiaomi for later in the year. Pixel 8 and 8 Pro were announced
the same day, and AOSP lists Android 14 builds made for them.

Google kept the dessert name inside the code. A change posted to AOSP in April
2022 named the release Upside Down Cake, and `Build.java` defines
`UPSIDE_DOWN_CAKE = 34` with the comment "Upside Down Cake.". Build IDs start
with U. Google's announcements only ever say Android 14.

## What it brought

- **Lock screen.** A rebuilt customization picker, lock screen templates for
  clocks, widgets and colors, custom lock screen shortcuts, and a monochromatic
  theme. Generative AI wallpapers came first to the Pixel 8.
- **Accessibility.** Font size goes up to 200%, on a non-linear curve so large
  text grows more slowly than small text. Google's launch post says the Pixel
  maximum was 130% before. Users also got "Flash notifications" and a
  hearing-aid setup flow.
- **Ultra HDR.** 10-bit HDR photos in a format that stays readable as a normal
  JPEG. An app opts in to HDR display per window.
- **Health Connect in the platform.** The health data store moves from a Play
  Store app into the system as a framework module, updated through Google Play
  system updates, and sits in Settings. It added exercise routes, and another
  app can read a route only after the user allows that route.
- **Credential Manager.** One platform API (`android.credentials`) for
  passwords, passkeys and federated sign-in. The Jetpack library brings it back
  to Android 4.4 through Google Play services.
- **Regional preferences.** Users pick temperature units, the first day of the
  week and the numbering system in "Regional preferences". Apps read them with
  calls such as `getTemperatureUnit()` and `getFirstDayOfWeek()`.
- **Languages.** The Grammatical Inflection API addresses the user in their
  grammatical gender. Per-app languages gained `setOverrideLocaleConfig()`, and
  AGP 8.1 generates the `LocaleConfig` file.
- **Screenshot detection.** An activity registers an
  `Activity.ScreenCaptureCallback` and learns that a screenshot was taken while
  it was visible. The app never gets the image, and the system tells the user
  the app noticed.
- **Predictive back.** Cross-activity and cross-task animations join the
  back-to-home animation from Android 13, with new callbacks for in-app
  transitions. The system animations stayed behind a developer option.
- **Background work.** User-initiated data transfer jobs are new: a
  JobScheduler job the user starts, such as a large download, that shows a
  notification and can run longer than a normal job.
- **Developer APIs.** Custom sharesheet actions, `PathIterator` and
  `Path.interpolate()`, custom meshes with AGSL shaders,
  `HardwareBufferRenderer`, lossless USB audio, and about 300 `java.base`
  classes updated to OpenJDK 17.
- **App stores.** Installers can ask for approval before downloading, claim
  update ownership with `setRequestUpdateOwnership()`, and wait until the app is
  not in use to update it.

The launch post also reported performance numbers from the beta population.
Cached processes used up to 50% fewer CPU cycles than on Android 13, cold app
starts fell 20% on 8 GB devices and over 30% on 12 GB devices, and ART code
size shrank by 9.3% on average.

## Security and privacy

On every Android 14 device:

- **Minimum installable target.** An app with `targetSdkVersion` below 23 fails
  to install with `INSTALL_FAILED_DEPRECATED_SDK_VERSION`. Google said malware
  targets 22 to dodge the runtime permissions of
  [Android 6.0](/notes/android-6-marshmallow/). Apps already installed before
  the upgrade stay, and `adb install --bypass-low-target-sdk-block` installs one
  for testing; there is no other way around the block.
- **Accessibility services.** A view can call
  `setAccessibilityDataSensitive()` so only services that declare
  `isAccessibilityTool` can read it or act on it. Malware often abuses
  accessibility services.
- **Media owners.** `MediaStore` redacts `OWNER_PACKAGE_NAME`, unless the owner
  app is always visible or the caller holds `QUERY_ALL_PACKAGES`.
- **PIN.** Android 14 encourages a six-digit PIN and unlocks without "Enter"
  once a correct six-digit or longer PIN is typed.
- **Cellular.** IT admins can stop managed devices from falling back to 2G, and
  a new toggle, where the manufacturer enables it, rejects null-ciphered
  connections so voice and SMS stay encrypted.
- **Platform.** AES-HCTR2 is the preferred filename encryption on devices with
  crypto instructions, and key attestation supports two IMEIs.

For apps that target API 34, implicit intents, runtime receivers, dynamic code
loading, zip entry names, background activity starts and screen capture all
became stricter. Each one is a row in
[the targeting table](#apps-targeting-api-34).

## Permissions

Android 14 added permissions for partial photo access, typed foreground
services, screenshot detection and user-initiated jobs, and tightened five
existing ones:

| Permission                               | What changed in API 34                                                                                  | What to declare                                                                                                                | What to remove or limit                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `READ_MEDIA_VISUAL_USER_SELECTED`        | New; tells the app the user shared only some photos and videos, and lets it reopen the selection        | Declare it next to `READ_MEDIA_IMAGES` and `READ_MEDIA_VIDEO` if you keep your own gallery picker                              | None of the three if the photo picker covers you                               |
| `READ_MEDIA_IMAGES` · `READ_MEDIA_VIDEO` | For apps targeting 34, the dialog adds "Select photos and videos", so a grant can be partial            | Keep both, as from API 33                                                                                                      | `READ_EXTERNAL_STORAGE` stays at `android:maxSdkVersion="32"`                  |
| `FOREGROUND_SERVICE_*`                   | New, one per service type, such as `FOREGROUND_SERVICE_CAMERA`; normal, granted at install              | The one for each type in `android:foregroundServiceType`, plus `FOREGROUND_SERVICE`                                            | Types you do not use; `shortService` needs no type permission                  |
| `DETECT_SCREEN_CAPTURE`                  | New, install-time; needed for screenshot detection callbacks                                            | Declare it if you register an `Activity.ScreenCaptureCallback`                                                                 | Nothing                                                                        |
| `RUN_USER_INITIATED_JOBS`                | New; needed for user-initiated data transfer jobs                                                       | Declare it if you build jobs with `setUserInitiated(true)`                                                                     | Nothing                                                                        |
| `SCHEDULE_EXACT_ALARM`                   | Denied by default for most new installs of apps targeting 33 or higher; kept by apps on upgrade         | Keep it; check `canScheduleExactAlarms()` and send the user to `ACTION_REQUEST_SCHEDULE_EXACT_ALARM`                           | Drop it if inexact alarms or WorkManager are enough                            |
| `USE_FULL_SCREEN_INTENT`                 | For apps targeting 34, only calling and alarm apps; Google Play revokes it from others from 31 May 2024 | Declare it only for calls or alarms; check `canUseFullScreenIntent()`                                                          | Remove it from every other app                                                 |
| `ACCESS_NETWORK_STATE` · `INTERNET`      | For apps targeting 34, required to schedule a job with a network constraint                             | Declare both if a job calls `setRequiredNetworkType()` or `setRequiredNetwork()`                                               | Nothing                                                                        |
| `BLUETOOTH_CONNECT`                      | For apps targeting 34, enforced on `BluetoothAdapter.getProfileConnectionState()`                       | Declare it and check the grant before the call                                                                                 | Nothing                                                                        |
| Health Connect permissions               | Health Connect is part of the platform; its permissions screen links to your rationale a new way        | An `<activity-alias>` for `VIEW_PERMISSION_USAGE` with category `HEALTH_PERMISSIONS`, guarded by `START_VIEW_PERMISSION_USAGE` | Keep the `ACTION_SHOW_PERMISSIONS_RATIONALE` activity for Android 13 and lower |

`SCHEDULE_EXACT_ALARM` also stays denied when app data is restored to an
Android 14 device. Calendar and alarm clock apps use `USE_EXACT_ALARM` instead,
which [Android 13](/notes/android-13/) introduced and Play allows only for them.
An exact alarm set with an `OnAlarmListener` needs neither permission.

One manifest for an app that runs on Android 13 and earlier and on 14 and
later. Keep only the blocks your app needs:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <!-- Photos and videos: the old permission up to API 32, the media ones
         from 33, partial access from 34 -->
    <uses-permission
        android:name="android.permission.READ_EXTERNAL_STORAGE"
        android:maxSdkVersion="32" />
    <uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />
    <uses-permission android:name="android.permission.READ_MEDIA_VIDEO" />
    <uses-permission android:name="android.permission.READ_MEDIA_VISUAL_USER_SELECTED" />

    <!-- Foreground service: the general permission plus one per type -->
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />

    <!-- Jobs with a network constraint -->
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

    <!-- Calling or alarm apps only -->
    <uses-permission android:name="android.permission.USE_FULL_SCREEN_INTENT" />

    <application>
        <service
            android:name=".PlaybackService"
            android:foregroundServiceType="mediaPlayback"
            android:exported="false" />
    </application>
</manifest>
```

An app that only adds photos or files to shared storage needs no read
permission at all; Google's guide caps `READ_EXTERNAL_STORAGE` at
`maxSdkVersion="28"` for that case.

![Four phone screens: a chat app, the dialog with Select photos and videos, Allow all and Don't allow, a picker with five photos chosen, and the chat app showing only those photos](./assets/selected-photos-access.png 'Selected Photos Access in Android 14: the user picks which photos and videos the app can see. Android Developers · CC BY 2.5')

Partial access changes during the app's life: the user can change it in
Settings without closing the app, so check the grant again between `onStart`
and `onResume`. An app targeting 33 that declares
`READ_MEDIA_VISUAL_USER_SELECTED` also gets the partial-access dialog; one
targeting 34 that does not declare it runs in a compatibility mode the system
controls. On a device upgraded from Android 13, apps keep the full access they
had.

The location dialog changed as well. If an app declared in Play's Data safety
form that it shares location with third parties, the dialog shows that. If an
app starts sharing location with third parties or for ads, the user gets a
notification within 30 days.

## What changed for your app

### All apps on Android 14

| Change                                                                    | What to do                                                                                   | How to check                                                       |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Apps targeting below 23 cannot be installed                               | Raise `targetSdkVersion` to at least 23                                                      | `adb install --bypass-low-target-sdk-block <file>.apk` for testing |
| `SCHEDULE_EXACT_ALARM` denied by default on new installs (target 33+)     | Call `canScheduleExactAlarms()` first; use inexact alarms or WorkManager when you can        | Lint `ScheduleExactAlarm`                                          |
| Exact alarms with an `OnAlarmListener` are dropped when the app is cached | Do not rely on listener alarms once the app leaves the screen                                | Compat `EXACT_LISTENER_ALARMS_DROPPED_ON_CACHED` (265195908)       |
| Cached apps are frozen shortly after leaving the screen                   | Run background work through services, JobScheduler or WorkManager                            |                                                                    |
| Context-registered broadcasts are queued while the app is cached          | Do not expect them on time; less important ones such as `ACTION_SCREEN_ON` wait, some merge  |                                                                    |
| Jobs that time out repeatedly can put the app in the restricted bucket    | Return from `onStartJob` and `onStopJob` quickly; log `getAppStandbyBucket()`                |                                                                    |
| `killBackgroundProcesses()` only kills your own processes                 | Stop trying to manage other apps' processes                                                  |                                                                    |
| Ongoing (`setOngoing(true)`) notifications can be dismissed               | Keep state in the app, not in the notification; call, media and lock-screen cases are exempt |                                                                    |
| Font scale up to 200%, non-linear                                         | Use `sp` for text and `lineHeight`; convert with `TypedValue.applyDimension()`               |                                                                    |
| `mlock()` limited to 64 KB per process (was 64 MB)                        | Check native code that locks memory                                                          |                                                                    |
| First GATT client's MTU request asks for 517 bytes; later ones ignored    | Make the peripheral answer with a size it supports; subtract 5 bytes of headers              |                                                                    |
| `MediaStore` redacts `OWNER_PACKAGE_NAME`                                 | Do not depend on knowing which app saved a file                                              |                                                                    |

### Apps targeting API 34

| Change                                                                        | What to do                                                                                        | How to check                                                                                                       |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Every foreground service needs `android:foregroundServiceType`                | Declare the type and its `FOREGROUND_SERVICE_*` permission; pass the type to `startForeground()`  | Lint `ForegroundServiceType` and `ForegroundServicePermission`; compat `FGS_TYPE_PERMISSION_CHANGE_ID` (254662522) |
| `FOREGROUND_SERVICE_TYPE_NONE` throws                                         | Pick a real type                                                                                  | Compat `FGS_TYPE_NONE_DISABLED_CHANGE_ID` (255038118)                                                              |
| Partial access to photos and videos                                           | Use the photo picker, or declare `READ_MEDIA_VISUAL_USER_SELECTED` and handle partial access      | Lint `SelectedPhotoAccess`                                                                                         |
| Implicit intents reach only exported components                               | Make internal intents explicit with `setPackage()`, or export the component                       | Lint `UnsafeImplicitIntentLaunch`; compat `IMPLICIT_INTENTS_ONLY_MATCH_EXPORTED_COMPONENTS` (229362273)            |
| A mutable `PendingIntent` with no component or package throws                 | Set the component or package on the intent                                                        | Lint `MutableImplicitPendingIntent`                                                                                |
| `registerReceiver()` needs an export flag                                     | Pass `RECEIVER_EXPORTED` or `RECEIVER_NOT_EXPORTED`; not for system-broadcast-only receivers      | Lint `UnspecifiedRegisterReceiverFlag`                                                                             |

| A visible app binding a service no longer lends its background activity start | Add `BIND_ALLOW_ACTIVITY_STARTS` to `bindService()` when the service must start an activity       |                                                                                                                    |

| `USE_FULL_SCREEN_INTENT` only for calling and alarm apps                      | Check `canUseFullScreenIntent()`; open `ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT` if needed       |                                                                                                                    |
| JobScheduler ANRs when `onStartJob` or `onStopJob` blocks                     | Move work off the main thread, or use WorkManager                                                 |                                                                                                                    |
| Network constraints in JobScheduler need `ACCESS_NETWORK_STATE`               | Declare it with `INTERNET`, or scheduling throws `SecurityException`                              | Compat `REQUIRE_NETWORK_PERMISSIONS_FOR_CONNECTIVITY_JOBS` (271850009)                                             |
| `BluetoothAdapter.getProfileConnectionState()` enforces `BLUETOOTH_CONNECT`   | Declare and request it before the call                                                            |                                                                                                                    |
| `TileService.startActivityAndCollapse(Intent)` throws                         | Pass a `PendingIntent` instead                                                                    | Lint `StartActivityAndCollapseDeprecated`                                                                          |
| `AccountManager` needs declared package visibility                            | Declare the packages you query in `<queries>`                                                     | Compat `ENFORCE_PACKAGE_VISIBILITY_FILTERING` (154726397)                                                          |
| Invalid regex group references throw (OpenJDK 17)                             | Test code that uses `java.util.regex.Matcher`                                                     | Compat `DISALLOW_INVALID_GROUP_REFERENCE`                                                                          |
| `UUID.fromString()` validates strictly (OpenJDK 17)                           | Test deserialization; bad input throws `IllegalArgumentException`                                 | Compat `ENABLE_STRICT_VALIDATION`                                                                                  |
| ProGuard can strip `computeValue` from `ClassValue` subclasses                | Test shrunk release builds that use Kotlin libraries relying on `ClassValue`                      |                                                                                                                    |

The compat list also holds changes few apps meet: sync APIs check authority
access, network service discovery moves to a platform mDNS backend, and
JobScheduler rejects negative network estimates and data transfer jobs that
miss part of their API. The behaviour changes page names the regex and UUID
flags without a change ID.

The foreground service rule is the one most apps hit. A missing type throws
`MissingForegroundServiceTypeException`; a missing type permission or runtime
prerequisite throws `SecurityException`.

```mermaid title="Starting a foreground service in an app targeting API 34"
flowchart TD
  start([Service calls startForeground]) --> type{Type declared in the manifest?}
  type -- No --> missing[MissingForegroundServiceTypeException]
  type -- Yes --> perm{FOREGROUND_SERVICE_TYPE permission declared?}
  perm -- No --> sec[SecurityException]
  perm -- Yes --> prereq{Runtime prerequisite met, such as CAMERA granted?}
  prereq -- No --> sec
  prereq -- Yes --> ok[Service runs in the foreground]
```

Android 14 adds five types: `health`, `remoteMessaging`, `shortService`,
`specialUse` and `systemExempted`. A `shortService` runs for about 3 minutes
and needs no extra permission. A `specialUse` service explains its use case in
a manifest `<property>`, and Google Play reviews it. Google recommends
WorkManager or user-initiated data transfer jobs for work that fits no type.

## Migrating to API 34

From `targetSdk 33` to 34, in this order:

1. **Update the toolchain.** Set `compileSdk 34` and use AGP 8.1.1 or later
   with Android Studio Hedgehog or later. Skipped, the new constants
   (`FOREGROUND_SERVICE_TYPE_HEALTH`, `READ_MEDIA_VISUAL_USER_SELECTED`) do not
   compile. Verify: the project builds and lint runs clean of new errors.
2. **Type every foreground service.** Add `android:foregroundServiceType`, its
   `FOREGROUND_SERVICE_*` permission, and request runtime prerequisites such as
   `CAMERA` before `startForeground()`. Skipped, the service throws and the app
   can crash. Verify: lint `ForegroundServiceType` and
   `ForegroundServicePermission`, then start each service on Android 14, once
   with its runtime permission denied.
3. **Handle partial photo access.** Move to the photo picker, or declare
   `READ_MEDIA_VISUAL_USER_SELECTED` and add a way to change the selection.
   Skipped, the system runs your picker in compatibility mode. Verify: lint
   `SelectedPhotoAccess`, then pick "Select photos and videos" on an Android 14
   device.
4. **Close implicit paths.** Make intents to your own unexported components
   explicit, set a package on mutable `PendingIntent`s, and pass an export flag
   to `registerReceiver()`. Skipped, callers get `ActivityNotFoundException` and
   the other two throw. Verify: lint `UnsafeImplicitIntentLaunch`,
   `MutableImplicitPendingIntent` and `UnspecifiedRegisterReceiverFlag`.
5. **Fix background starts and screen capture.** Opt in where a
   `PendingIntent` or bound service must start an activity, and ask for consent
   before each `MediaProjection` session. Skipped, activities fail to open and
   capture throws `SecurityException`. Verify: run those flows on Android 14.
6. **Check jobs.** Return quickly from `onStartJob` and `onStopJob`, and
   declare `ACCESS_NETWORK_STATE` for network constraints. Skipped, jobs ANR or
   fail to schedule. Verify: run each job at once with
   `adb shell cmd jobscheduler run -f <package> <job ID>`.
7. **Go through the smaller rows** of the targeting table that apply to you:
   full-screen intents, read-only dynamic code, zip entries, Bluetooth, tiles,
   `AccountManager`, regex and UUID parsing.
8. **Test the result** on an Android 14 device or emulator with
   `targetSdk 34`. To isolate one change, toggle it on a debuggable build in
   Developer options > "App Compatibility Changes", or with
   `adb shell am compat disable <change ID> <package>`.

Whatever your target, also check the all-apps table: exact alarms are denied
by default, and a `targetSdk` below 23 no longer installs.

Skipping several levels at once: do each version's steps in order, starting
from [Android 13](/notes/android-13/#migrating-to-api-33) if you target 32 or
lower.

## What lasted

- **Minimum installable target** kept rising: Android 15 blocks apps that
  target below 24.
- **Foreground service types** stayed mandatory. Android 15 added a
  `mediaProcessing` type and limits `dataSync` services to 6 hours in 24.
- **Predictive back** left the developer option in Android 15. System
  animations now play for every app that opted in.
- **Selected photo access** and `READ_MEDIA_VISUAL_USER_SELECTED` are still how
  a gallery app gets partial access.
- **Health Connect** and **Credential Manager** remain platform APIs.
- **USB webcam.** Android 14 enabled the UVC gadget driver in the Generic
  Kernel Image by default; using the device as a USB webcam came with the
  Android 14 QPR1 update, not the first release.

## Worth knowing

- The Easter egg is a spaceflight game. Tap "Android version" in Settings three
  times, then long-press the logo. You steer a ship by dragging; the screen
  shows thrust, position and velocity, and `LND:` with the planet's name when
  you land.
- Each game starts in a random star system with 1 to 10 planets, each named
  after the system plus a number.
- The starfield on the logo screen draws 34 stars. The constant reads
  `NUM_STARS = 34; // Build.VERSION_CODES.UPSIDE_DOWN_CAKE`.
- Its top speed is `MAX_WARP = 10f`, with the comment "after all these years".
