Android 17 is the release that made adaptive layouts mandatory and gave every
app a memory ceiling. Apps targeting API 37 can no longer keep their
orientation or aspect ratio locks on tablets and foldables, and the system now
kills a process that outgrows a limit set by the device's RAM. For developers,
most of what breaks waits until `targetSdk` reaches 37.

This is the overview. Six parts follow it, in order: the four betas, from
[Beta 1](/notes/android-17/beta-1/) to [Beta 4](/notes/android-17/beta-4/),
with [Beta 3](/notes/android-17/beta-3/) covering every new API at platform
stability; [what breaks on targetSdk 37](/notes/android-17/stable/); and
[the memory limits](/notes/android-17/memory-limits/).

## At a glance

|                                 |                                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Version                         | Android 17                                                                                             |
| API level                       | 37 (37.1 from QPR1; 37.2 in the QPR2 beta)                                                             |
| Name                            | Cinnamon Bun, internal; visible in the SDK constant. Public name: Android 17                           |
| `Build.VERSION_CODES`           | `CINNAMON_BUN` (`VERSION_CODES_FULL.CINNAMON_BUN_1` for QPR1)                                          |
| Release                         | Pixel rollout began 16 June 2026                                                                       |
| Launch devices                  | Pixel 6 and newer by update; Samsung Galaxy Z Fold8 Ultra, Z Fold8 and Z Flip8, announced 22 July 2026 |
| Google Play target-API deadline | Not announced as of October 2026                                                                       |

Google released Android 17 on 16 June 2026 for the Pixel 6 and newer, and published the source to AOSP the same day. The first
release build is `CP2A.260605.016`, tag `android-17.0.0_r1`, with the June 2026
security patch.

Google skipped developer previews this time: the Canary channel did that job,
and Android 17 went straight to beta. Beta 1 came out on 13 February 2026 and
Beta 2 on 26 February. The API surface locked at Beta 3, on 26 March. Beta 4,
on 16 April, was the last scheduled beta; a bug-fix Beta 4.1 followed on
1 June.

Samsung announced the Galaxy Z Fold8 Ultra, Z Fold8 and Z Flip8 on 22 July
2026; their spec sheets list Android 17 with One UI 9.

The name Cinnamon Bun leaked in August 2025, when a Google source showed
Android Authority the codename for API level 37.0. The SDK constant confirms
it: `CINNAMON_BUN = 37`. Like Baklava for Android 16, it is internal, but
developers see it in code.

## What it brought

- **Adaptive-first.** Google's launch post calls Android 17 "an adaptive-first
  development standard". Any app can become a floating **App Bubble** by
  long-pressing its icon, large screens get a Bubble Bar in the taskbar, and
  desktop mode gets interactive picture-in-picture windows.
- **Compose-first.** Google declared that all new UI APIs, libraries and
  guidance will be built only for Jetpack Compose. `android.widget` Views and
  View-based Jetpack libraries such as Fragments and RecyclerView are now in
  maintenance mode: critical bug fixes only.
- **AppFunctions.** Apps can expose their actions as tools that AI agents,
  such as Gemini, discover and run on the user's behalf. The Jetpack library
  is in alpha; the Gemini integration was in private preview at launch.
- **Fewer activity restarts.** Changes such as `CONFIG_KEYBOARD` or
  `CONFIG_COLOR_MODE` no longer recreate the activity by default; it gets
  `onConfigurationChanged()` instead. `android:recreateOnConfigChanges`
  restores the old behaviour.
- **Continue On.** `setHandoffEnabled()` lets the tablet taskbar offer the app
  the user just had open on their phone, deep-linked to where they left off.
- **Performance tools.** `ProfilingManager` gains `TRIGGER_TYPE_COLD_START`,
  `TRIGGER_TYPE_OOM`, `TRIGGER_TYPE_KILL_EXCESSIVE_CPU_USAGE` and
  `TRIGGER_TYPE_ANOMALY`. For apps targeting 37, `MessageQueue` is lock-free.
- **Media and camera.** `ImageFormat.RAW14`, vendor-defined camera
  extensions, camera device type queries, an Extended HE-AAC encoder, H.266
  (VVC) support for OEMs, and constant-quality video recording.
- **Hearing aids.** `AudioDeviceInfo.TYPE_BLE_HEARING_AID` tells hearing aids
  apart from headsets, and users can route notifications, ringtones and alarms
  to the hearing aid or the phone speaker.
- **Pickers instead of permissions.** A system contact picker
  (`ACTION_PICK_CONTACTS`), a portrait photo picker grid, a system-rendered
  location button, and a screen-wide eyedropper (`ACTION_OPEN_EYE_DROPPER`).

The full API list at platform stability is in the
[Beta 3 part](/notes/android-17/beta-3/).

## Security and privacy

- **Post-quantum cryptography.** Android Keystore can generate ML-DSA keys in
  secure hardware through the standard JCA APIs, and APK Signature Scheme v3.2
  pairs a classical signature with an ML-DSA one.
- **Encrypted Client Hello.** For apps targeting 37, TLS uses ECH when the
  networking library and the server both support it. `<domainEncryption>` in
  the network security config turns it on or off per domain.
- **Certificate Transparency** is on by default for apps targeting 37; on
  Android 16 it was opt-in.
- **Safer native code loading.** For apps targeting 37, `System.load()` throws
  `UnsatisfiedLinkError` unless the file is read-only, extending the Android 14
  rule for DEX and JAR files.
- **SMS OTP.** WebOTP messages are held for three hours from every app that is
  not the verified recipient. For apps targeting 37, the hold covers standard
  OTP messages too.
- **Activity security.** For apps targeting 37, background activity launch
  restrictions extend to
  `IntentSender`, and `MODE_BACKGROUND_ACTIVITY_START_ALLOWED` gives way to
  granular modes such as `MODE_BACKGROUND_ACTIVITY_START_ALLOW_IF_VISIBLE`.
- **Theft protection.** Find Hub's "Mark as lost" can require biometrics on
  top of the PIN, so a thief who saw the PIN cannot turn off tracking. Remote
  Lock and Theft Detection Lock are on by default on new, reset or upgraded
  Android 17 devices.
- **Passwords on physical keyboards.** For apps targeting 37, the last typed
  character is no longer shown when the user types on a physical keyboard;
  touch and physical input have separate settings.
- **Keystore and profiles.** Non-system apps targeting 37 can own at most
  50,000 Keystore keys, and loopback traffic between profiles is blocked by
  default.

## Permissions

- **`ACCESS_LOCAL_NETWORK`.** Apps targeting 37 lose local network access
  unless they hold this runtime permission or use a system device picker. It
  belongs to the `NEARBY_DEVICES` group, so users who already granted another
  nearby devices permission are not asked again.
- **Contacts.** The contact picker returns only the fields the user picks,
  without `READ_CONTACTS`. For apps targeting 37, Contacts Provider hides
  `ACCOUNT_NAME`, `ACCOUNT_TYPE` and `ACCOUNT_TYPE_AND_DATA_SET` in the data
  view, and queries without `READ_CONTACTS` get strict SQL checks.
- **Location button.** `USE_LOCATION_BUTTON` lets an app embed the
  system-rendered button that grants precise location for the session only,
  with no dialog.
- **Pinned windows.** `USE_PINNED_WINDOWING_LAYER` lets an app ask for an
  always-on-top, interactive window in desktop mode.
- **NPU access.** Apps targeting 37 that use the neural processing unit
  directly must declare `FEATURE_NEURAL_PROCESSING_UNIT`, or they are blocked.

## What changed for your app

### All apps on Android 17

| Change                                                                                                         | What to do                                                                                                         |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| A process over its RAM-based memory limit is killed with no stack trace                                        | Read `ApplicationExitInfo` for `"MemoryLimiter:AnonSwap"`; see the [memory part](/notes/android-17/memory-limits/) |
| Audio playback, focus and volume changes need a visible activity or a foreground service (not `SHORT_SERVICE`) | Start a `mediaPlayback` service while visible; Media3's `MediaSessionService` does it                              |
| WebOTP SMS are held for three hours from apps that are not the recipient                                       | Use SMS Retriever or SMS User Consent                                                                              |
| Cross-profile loopback traffic is blocked                                                                      | Do not rely on localhost between work and personal profiles                                                        |

### Apps targeting API 37

| Change                                                                                                    | What to do                                                                         |
| --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| On `sw600dp` displays, orientation, resizability and aspect ratio limits are ignored; the opt-out is gone | Build for any window size; games declaring `android:appCategory="game"` are exempt |
| `static final` fields cannot be changed by reflection or JNI                                              | Update libraries that rewrite them; JNI writes crash the process                   |
| `MessageQueue` is lock-free; its private fields are useless to reflection                                 | Update Espresso and Robolectric; use `TestLooperManager`                           |
| Local network access is blocked by default                                                                | Use a device picker, or request `ACCESS_LOCAL_NETWORK`                             |
| Background audio needs a foreground service with while-in-use capability                                  | Start the service from a user action                                               |
| Standard SMS OTP messages are held for three hours                                                        | Move to SMS Retriever or SMS User Consent                                          |
| `setContentCaptureEnabled(false)` no longer disables Content Capture                                      | Use `FLAG_SECURE`                                                                  |
| Widget `RemoteViews` over the bitmap memory limit throw `IllegalArgumentException`                        | Downscale bitmaps and icons in widgets                                             |

The reasoning behind each change, and the order to tackle them in, is in
[Android 17: what breaks on targetSdk 37](/notes/android-17/stable/).

## Android 17 QPR1, QPR2 and minor SDKs

[Android 16](/notes/android-16/) shipped one minor SDK, in its December
release. Android 17 has two so far.

- **QPR1 (API 37.1).** Its release notes list API diffs from 37 to 37.1 and
  say it reached platform stability at Beta 6. It reached Pixel phones on
  15 September 2026, with the September Feature Drop. The API reference lists
  `VERSION_CODES_FULL.CINNAMON_BUN_1`, "Android 17, minor release 1", added
  in version 37.1.
- **QPR2 (API 37.2, beta).** Google says it "includes a minor SDK release"
  with "no planned behavior changes". Beta 7.1 came out on 16 October 2026,
  and the reference already lists `CINNAMON_BUN_2`. Two changes still reach
  apps: call-forwarding USSD codes no longer work with `CALL_PHONE` alone, and
  self-broadcasts are delivered more efficiently, for every app.

The check stays the same as in Android 16: compare `SDK_INT_FULL` against the
`VERSION_CODES_FULL` constant.

## What lasted

It is too early to say what later versions kept. Google has announced two
follow-ups: from Android 18, the system stops granting URI permissions
implicitly for some intents, and `usesCleartextTraffic` will be deprecated in a
future release in favour of a network security config. Google Play has not set
a date for API 37; the current rule asks for API 36 from 31 August 2026.

## Worth knowing

- The `Build.java` comment for the constant is two words: "Cinnamon Bun." In
  `VERSION_CODES_FULL` it is just "Android 17." Nothing like the Shakespeare
  line AOSP left on `S_V2`.
- The name keeps the order. The dessert alphabet restarted at Baklava, a B, for
  Android 16; Cinnamon Bun is the C that follows. Android 17 build IDs start
  with C as well: `CP2A.260605.016`.
- The Easter egg opens with 17 dots in a circle. Trace through all of them in
  one stroke and back to the first, and the logo appears; lift your finger and
  the path resets. Keyboard users skip it: the code says "skip the cute
  star-drawing minigame".
- The starfield changed direction. The source comment reads "New in C: we're
  zooming out from the center this time. Classic." The warp ceiling is still
  `16f` with the comment "must go faster".
- The generational garbage collector is in both Google's Android 16 QPR2 post
  and its Android 17 launch post. AOSP settles it: the `use_generational_cmc`
  flag was first enabled in the Android 16 QPR2 release configuration, and
  Android 17 inherits it.
